🗺 Application Overview

The Field Service Schedule Board is a web application used by dispatchers and service managers to view, schedule, and manage field technician bookings synced from Microsoft Dynamics 365 Field Service (CRM). It provides a live calendar view of every technician's work across all regions, supports drag-and-drop rescheduling, and writes changes back to Dynamics in real time.

ℹ️
Access is controlled by the Admin Console. All users must sign in with their Microsoft work account (Entra ID). The Admin Console maps each user to either Read-Only (Viewer) or Read/Write (Editor).

Who uses this app

  • Dispatchers (Editors) — schedule, reschedule, create blocks & placeholders, add notes, sync to CRM
  • Managers / Viewers — read-only board view, utilization reporting, work order detail lookup

What it does

  • Live calendar board for all technicians across all regions
  • Drag-and-drop booking rescheduling (queued or direct CRM write)
  • Schedule blocks: Travel Time, PTO, Custom
  • Placeholder (potential) jobs for pre-sales or unconfirmed work
  • Utilization tracking and reporting
  • Calendar Report: PDF, Word, and email delivery to technicians

🎓 User Training Guide

This section walks through every common task a dispatcher or manager needs to perform. Screenshots are described in text — the board renders live data from Dynamics.

2.1 Signing In

🔐 How to log in

  1. Navigate to the app URL. If you are not signed in, you will see a "Sign in required" card.
  2. Click Sign in with Microsoft. Your browser opens a Microsoft login page (this cannot be embedded in an iframe — if you see it blocked, open the app URL directly in its own tab).
  3. Sign in with your company Microsoft work account.
  4. The Admin Console checks your account. If you have been granted access, you are redirected back to the board.
  5. Your role (Viewer or Editor) is set at login. It applies for the entire session (30 days rolling). Editor controls are hidden entirely from Viewer sessions.
⚠️
If you see "Access denied", your account has not been granted permission to this application. Contact your system administrator to be added in the Admin Console.

2.2 Board Controls & Navigation

The controls row sits above the board. All buttons are visually outlined for clarity. Two groups exist:

⬅ Date Navigation (left side)

  • ← / → arrows — move back or forward by one week (Week view) or one month (Calendar view)
  • Today — jump to the current week or month containing today
  • Next quarter — jump to the Monday of the first week of the next calendar quarter (e.g. clicking in August 2026 jumps to the week of October 1, 2026)
  • Next year — jump to the same date one year from now (e.g. August 11, 2026 → week of August 11, 2027)

These buttons work identically in both Week and Calendar views, and in the focused single-technician Calendar view.

⚙ View & Grouping (right side)

  • Week — shows a 7-day swimlane grid, one row per technician, one column per day. Chips show WO number, customer, city/state, and duration.
  • Calendar — shows 4–5 weeks in a stacked monthly grid. Chips are condensed. Click a technician row's header to enter the focused single-tech view.
  • By Tech Region — group technicians under their CRM service territory (R1, R2, R3, R4, etc.)
  • By Service Location — group work orders by the state/city of the job site
  • Calendar Report — opens the calendar report dialog (visible to Editors only)

Region & Technician Filters

Below the controls row, a row of region toggle pills lets you show or hide entire regions. Click a region pill to toggle it; Select All and Clear buttons reset the selection. A similar technician filter panel appears when data is loaded — narrow down to specific technicians by name.

2.3 Board Views

📅 Week View

The default view. Shows Mon–Sun (or Mon–Fri depending on settings) for one week. Each region is a collapsible section header; each technician is one row. Chips in a cell are stacked vertically.

  • Shows work order number, customer name, city/state, start–end time or duration
  • Long text wraps within the chip — no text is hidden
  • Multi-day bookings span across columns
  • Conflict indicators (amber ring) show double-booked slots

🗓 Calendar View

Month-at-a-glance view. Regions and technicians are stacked in a compact monthly grid. Best for planning and spotting gaps over a longer horizon.

  • Click any technician's name to enter focused single-tech view — a 13-week stacked calendar showing only that technician's schedule
  • The focused view has its own Today / Next quarter / Next year navigation
  • Click All technicians to return to the full board

👷 Single-Tech Focused View

Entered by clicking a technician's name in Calendar view. Shows 13 weeks (≈ one quarter) of that technician's schedule in a stacked Mon–Fri grid.

  • Full chip detail: WO number, customer, city/state, duration, notes
  • Blocks (Travel Time, PTO, Custom) and Potential Jobs are shown inline
  • Navigate with the Today / Next quarter / Next year / ← → controls in the view header

2.5 Rescheduling a Job Editor Only

✏️ Option A — Drag & Drop (quick move)

  1. Find the booking chip you want to move. Only the start-day chip of a multi-day booking is draggable; single-day chips are always draggable.
  2. Click and hold the chip until the cursor changes to a grab hand.
  3. Drag to the target technician's row and target day column. The cell highlights when it accepts the drop.
  4. Release. The chip moves immediately on screen and a write-back is queued. A spinning sync icon confirms it is pending CRM save.
  5. Use the Edit Booking dialog (click the chip) if you also need to change the start/end times.

✏️ Option B — Edit Dialog (full control)

  1. Click the booking chip to open the Work Order Detail drawer.
  2. Click Reschedule (or the edit button on the chip).
  3. In the dialog: change the Start time, End time, or Technician.
  4. Click Save to CRM to write directly to Dynamics (immediate), or Queue to add to the pending write-back list for batch processing.
  5. The board refreshes. A sync icon on the chip confirms the save is in flight.
ℹ️
Conflict detection: If the technician you are scheduling already has another booking that overlaps with the new times, the chip gains an amber ring ⚠️ and a warning is shown. You can proceed anyway or pick a different slot.

2.6 Adding Schedule Blocks Editor Only

Schedule blocks (Travel Time, PTO, Custom) are local entries — they live in the app's database, not in Dynamics. Use them to mark a technician as unavailable or to annotate planned travel.

➕ Adding a block

  1. Hover over the technician's row for the target day. A faint + Add button appears in the cell.
  2. Click + Add. The Add dialog opens.
  3. Choose the Type:
    • Potential Job — unconfirmed prospective job (see §2.7 below)
    • Travel Time — marks travel or drive time
    • PTO — marks paid time off
    • Custom — any other annotation; requires a title
  4. Set Start time and End time (defaults: 8:00 AM – 5:00 PM for Potential Jobs).
  5. Optionally add Notes. Multi-line notes are supported — press Enter for a new line; each line shows as a separate bullet on the chip.
  6. Pick a Colour from the colour palette if you want to override the region default.
  7. Click Save. The chip appears immediately on the board.

Switching between Type options in the dialog automatically updates the colour picker to the region default for that type (e.g. switching to Custom in R4 selects Orange). If you manually pick a colour first, that manual choice is preserved when you switch types.

✏️ Editing or deleting a block

  • Click the chip to open the edit dialog. All fields are editable.
  • Click the small ✕ in the chip corner to delete it immediately (no confirmation dialog).
  • In the edit dialog, click Delete for a confirmation-prompted delete.
  • Multi-day blocks: drag the start-day chip to move the block's start date; drag the resize handle on the end-day chip to extend or shorten the block.

2.7 Adding Potential (Placeholder) Jobs Editor Only

Potential jobs let you pre-schedule speculative or unconfirmed work on the board without creating a Dynamics booking. They are visually distinct (dashed border + diagonal stripe) and are counted separately in utilization.

➕ Adding a potential job

  1. Click + Add in a technician's day cell and choose Potential Job.
  2. Fill in the fields:
    • Service location — search the CRM service location database by location ID, name, or city. Selecting a CRM location auto-fills customer name, city, and state.
    • Customer name — free-text if no CRM location is linked.
    • City / State — shown on the chip.
    • Status — optional. Choose from: PO Received, Credit Hold, Quote Sent, Waiting on Parts, Site Survey Needed, On Hold, Cancelled, None.
    • Start / End time — default 8:00 AM – 5:00 PM.
    • Notes — free text; multi-line supported.
    • Colour — defaults to Yellow for R4; other regions default to their region colour.
  3. Click Save. The potential job chip appears on the board with a dashed border.
ℹ️
Service Location Picker tip: Type at least 2 characters to search. The picker searches by location ID (e.g. S402310-2), address name, city, and state across all ~6,600+ active CRM service locations. If the CRM is temporarily unavailable, you can still enter the customer name and city manually.

2.8 Scheduling Unscheduled Jobs Editor Only

The Unscheduled Jobs panel slides out from the right side of the board and lists all work orders with no active booking.

📋 Using the Unscheduled Jobs panel

  1. Click the Unscheduled Jobs button (visible in the board). The panel opens on the right.
  2. Each job card shows: WO number · Customer · City/State · Estimated duration · Due date · Best-fit technician suggestions (ranked by nearby job density — the algorithm prefers techs who already have jobs in the same area).
  3. Jobs are grouped into buckets: Overdue, Due this week, Due next week, Due later, No due date.
  4. Click a best-fit technician suggestion to navigate the board to that technician.
  5. Drag the job card from the panel onto the board — drop it on a technician's day cell. An Edit Booking dialog opens to confirm the start/end times before the booking is created in Dynamics.
  6. Alternatively, click Schedule on the card to open the dialog directly without dragging.

2.9 Dispatcher Notes Editor Only

Notes can be attached to any CRM booking. They are stored in the app's local database (not in Dynamics) and shown on the chip in italic text and in the work order detail drawer.

📝 Adding or editing a note

  1. Click the booking chip to open the Work Order Detail drawer.
  2. Scroll to the Dispatcher Note field at the bottom of the drawer.
  3. Type your note. Multi-line notes are supported.
  4. Click Save note. The note appears on the chip immediately.

Notes persist even if the booking is rescheduled to a different technician or time. They are tied to the booking ID, not the time slot.

2.10 Searching Jobs

The global search bar is at the top of the board. It searches across scheduled, unscheduled, and potential jobs simultaneously.

  • Type at least 2 characters. Results appear after a 200 ms debounce.
  • Results are categorised: Scheduled, Potential, Unscheduled.
  • Each result shows the work order number, customer, technician (if scheduled), and location.
  • Clicking a result navigates the board to the relevant date and highlights the matching chip.
  • Chips that do not match the search are dimmed (20% opacity) while the search is active.

2.11 Resource Utilization

The Resource Utilization panel (expandable at the bottom of the board) shows booked hours vs capacity for each technician, grouped by region.

Reading the utilization panel

  • Bar chart per technician — filled portion = utilized hours ÷ capacity hours. The bar turns red if over 100%.
  • Breakdown: CRM job hours are shown in the region colour; Potential Job hours are shown as a secondary segment.
  • Default capacity: 40 hours/week (8 h/day × 5 days). The cap is applied server-side.
  • View toggles: Week / Month / Quarter — each recalculates utilization over the selected period.

Filtering the utilization panel

  • Use the region filter pills within the utilization panel to narrow to specific regions.
  • The panel respects the same region filters as the board above.
  • Utilization minutes already include placeholder (potential) job minutes server-side — they are never double-counted.

2.12 Calendar Report Editor Only

The Calendar Report generates a personal schedule summary for one or more technicians across a chosen date range. It can be previewed in-app, downloaded as PDF or Word, or emailed directly to technicians via Microsoft Graph. All output formats use larger, more readable typography for easy reading on screen and in print.

📄 Generating a Calendar Report

  1. Click Calendar Report in the controls row (visible only to Editors when data is loaded).
  2. The Calendar Report dialog opens. Choose how to define the date range using the Month range or Custom toggle:
    • Month range — select a start month from the dropdown then pick a span of 1–6 months.
    • Custom — pick an exact start date and end date using the date picker popovers. The end date picker automatically prevents selecting a date before the chosen start date. The Load Schedule Data button stays disabled until both dates are set.
  3. Click Load Schedule Data to fetch the schedule for the chosen range.
  4. Events included in the report:
    • ✅ Scheduled CRM bookings (customer name + city/state + WO number on separate lines)
    • ✅ Potential (placeholder) jobs
    • ✅ Travel Time blocks
    • ✅ PTO blocks
    • ◻️ Include Custom Blocks is unchecked by default, so reports behave as before. Check it to include Custom blocks in the PDF, Word download, and emailed PDF; Custom blocks remain visible in the in-app preview.
  5. Select one or more technicians from the technician picker in the dialog.
  6. Choose an action:
    • Download PDF — generates a multi-page PDF. Each page is one technician, with large readable font and event chips per day.
    • Download Word (.docx) — same layout as PDF, in an editable Word document.
    • Send Email — sends the report directly to the technician's work email (resolved from CRM) via Microsoft Graph. The email greeting uses the technician's first name; the sign-off uses the sending user's first name.
ℹ️
Multi-day bookings appear on every weekday they span in the report. A booking from Monday to Thursday shows on Mon, Tue, Wed, Thu. The report uses a half-open interval [start, end) so events ending at midnight on Friday do not bleed into Saturday.

2.13 Other Reports

Completed Not Approved

Service orders that have reached Completed status but not yet been approved. Filter by region, year, month. Useful for billing pipeline management.

Approved Not Invoiced

Service orders approved but not yet exported to the invoicing system (AX). Filter by region. Flags stalled invoicing.

Weekly Approved

Volume of approved orders grouped by approver and week. Filter by region, approver, year, month. Tracks throughput per approval workflow.

Create blocks for any technician on any date. Blocks carry optional title, notes, duration, and colour override. Multi-day blocks are draggable (start) and resizable (end). Stored in local PostgreSQL, not in Dynamics. Travel Time is the user-facing label (was "Drive Time").

Editor Only

Pre-schedule unconfirmed or prospective jobs. Store customer name, city/state, service location (CRM-linked or freeform), notes, colour, and status. Defaults to 8:00 AM – 5:00 PM. R4 colour default: Yellow. Rendered with dashed border + diagonal stripe overlay.

All Users

Editor Only

Attach free-text notes to any CRM booking. Stored locally; shown in italic on the chip and in the detail drawer. Notes survive rescheduling.

Per-technician schedule summary for any chosen date range. Select dates by month range (1–6 months) or an exact custom start/end date using date picker popovers. Personalized greetings (first-name based). Larger, readable typography throughout all output formats.

Editor Only

R4 Colour Defaults

R4 region uses type-specific colour defaults: Sky Blue for scheduled jobs and standard blocks, Yellow for Potential Jobs, Orange for Custom blocks. Overrides are saved per-entry and persist across edits.

All Users

CRM Mirror & Write-back

All read data comes from a PostgreSQL mirror of Dynamics (fast, no throttling). Writes go directly to Dynamics Dataverse via REST API. Two write paths: queued (batch) or direct-save (immediate). Sync pending indicator on chips during the 22-second CRM write window.

All Users

Service Location Detail

Navigate to /service-location/:id to view full address, contact, and equipment list (with calibration dates) for any CRM service location. Linked from potential job chips when a CRM location is attached.

🔒 Security & Permissions

Authentication Flow

Authentication uses Microsoft Entra ID (Azure AD) via OAuth 2.0 / OIDC. The MSAL Confidential Client handles the authorization code exchange server-side — no tokens are ever sent to the browser. After a successful code exchange, the server calls the Admin Console to verify that the user is explicitly permitted to access this application.

🛡 Session Security

  • Sessions stored in PostgreSQL (connect-pg-simple), not in-memory
  • Session ID regenerated after every successful login (session fixation prevention)
  • HttpOnly cookie — inaccessible to JavaScript
  • Secure flag set automatically in production
  • SameSite: Lax in production; None in development (required for Replit iframe preview)
  • Rolling 30-day expiry
  • SESSION_SECRET required in production

🔀 Open Redirect Prevention

The returnTo parameter on the login route is sanitised:

  • Must be a same-origin absolute path (starts with /)
  • Rejected if it starts with // or /\
  • External URLs are silently discarded; fallback is /

Role Model

✏️ Editor (Read/Write)

Assigned when Admin Console returns a role string containing read/write (case-insensitive). Can perform all read operations plus:

  • Create / update / delete schedule blocks
  • Create / update / delete placeholder jobs
  • Queue or directly save CRM booking changes
  • Trigger write-back sync
  • Write and delete booking notes
  • Generate and email Calendar Reports
  • Trigger CRM mirror sync and backfill (admin routes)

👁 Viewer (Read-Only)

Assigned when Admin Console returns an allowed user with a non-editor role. Can:

  • View the schedule board (all views and date ranges)
  • View work order details
  • View utilization reports
  • View service location details
  • View write-back queue status
  • View booking notes
  • Search across all jobs

All write UI controls are hidden entirely in the frontend. Any write API call is rejected with HTTP 403 server-side regardless.

Admin Console Fallback

If the Admin Console is unreachable or returns a malformed response at login time, the server falls back to the app.app_user table in the FS database. A user with role = 'editor' or role = 'admin' gets editor access; all other active users get viewer access; inactive users are denied (401).

✅
Defence in depth: Write operations are blocked at both layers. The API middleware rejects 403 for any viewer attempting a write, regardless of what the frontend shows. There is no path for a viewer to perform a write operation by manipulating the UI.

🔗 External Integrations

🔵 Microsoft Entra ID

Purpose: User authentication (OAuth 2.0 / OIDC)

Flow: Authorization Code with PKCE (server-side MSAL Confidential Client)

  • Authority: https://login.microsoftonline.com/{TENANT_ID}
  • Redirect URI: {APP_URL}/api/auth/callback

Env vars: ENTRA_TENANT_ID, ENTRA_CLIENT_ID, ENTRA_CLIENT_SECRET, ENTRA_REDIRECT_URI

🛡 Admin Console

Purpose: Per-user app entitlement (allowed + role)

Called on: Every login. Not on API requests.

Endpoint: GET {ADMIN_CONSOLE_URL}/api/access-check

Params: entraObjectId, app=Field Service Calendar

Headers: X-API-Key: {ADMIN_CONSOLE_API_KEY}

Response: { allowed: boolean, reason: string|null, roles: string[] }

Env vars: ADMIN_CONSOLE_URL, ADMIN_CONSOLE_API_KEY

🟠 Microsoft Dynamics 365 / Dataverse

Purpose: Source of truth for work orders and bookings. Write target for reschedules.

  • CRM Mirror DB — PostgreSQL replica of Dynamics, synced periodically. Used for all read queries.
  • Dataverse REST API — used for write-backs only (PATCH/POST to msdyn_resourcebookings)

Env vars: D365CRM_DATABASE_URL, DATAVERSE_ENV_URL, DATAVERSE_TENANT_ID, DATAVERSE_CLIENT_ID, DATAVERSE_CLIENT_SECRET

📧 Microsoft Graph (Calendar Report Email)

Purpose: Send Calendar Report HTML emails on behalf of the app to technicians.

Permission required: Mail.Send on the app registration used for Graph (separate from the Entra login app registration — the login app registration does not have Mail.Send).

Behaviour: Recipient email is resolved server-side from the CRM systemuser record linked to the technician. Client-provided emails are never trusted. Greeting uses the technician's first name; sign-off uses the sending dispatcher's first name. Both First Last and Last, First name formats are supported.

Env vars: CLIENT_ID, CLIENT_SECRET, TENANT_ID (Graph app registration credentials)

Shared API Client Library

@workspace/api-client-react is a generated TypeScript library created from the OpenAPI specification via Orval. It provides:

  • All TypeScript request/response interfaces (e.g. ScheduleBlock, PlaceholderJob, WbWorkOrder, WbServiceLocation)
  • React Query hooks for every endpoint (e.g. useGetWbScheduleBoard(), useCreateWbScheduleBlock(), useListWbServiceLocations())
  • A configurable customFetch layer supporting base URL and global 401 callback
  • Typed error classes: ApiError and ResponseParseError
⚠️
The generated dist files (lib/api-client-react/dist/) must be rebuilt and committed whenever the OpenAPI spec changes. Out-of-date dist files cause missing-export type errors at build time.
