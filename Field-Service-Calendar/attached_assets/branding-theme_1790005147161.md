# Application Branding & Theme Standard

## Purpose

All internally developed applications should provide a consistent company
look and feel regardless of business function or developer.

## Design Principles

1. Simple over decorative.
2. Consistent over application-specific.
3. Readability over visual complexity.
4. Desktop-first for operational applications.
5. Responsive where practical.
6. Accessibility should be considered in all UI components.

## Brand Colors

The application theme should use the established corporate
digital-transformation palette.

### Primary Palette

#### Background

Hex: "#00281D"

Usage:
- Application background
- Primary workspace background
- Dark navigation/header areas

#### Primary Accent

Hex: "#B7FF00"

Usage:
- Primary actions
- Active navigation
- Positive status
- Selected/highlighted elements
- Key visual emphasis

#### Secondary Text

Hex: "#C2D2BE"

Usage:
- Secondary information
- Supporting context
- Metadata
- Less prominent labels

#### Primary Text

Color: White or very light grey

Usage:
- Primary headings
- Primary order/business information
- Main labels and values
- Important content displayed against dark backgrounds

Do not use black text against the dark green background.

### Status Colors

Success / Active:
- Use "#B7FF00"
- Indicates active, positive, complete, or healthy status

Warning / HOLD:
- Use amber
- Indicates warning, pending action, or HOLD status

Error / STOPPED:
- Use red
- Indicates overdue, stopped, failed, or serious exception

Information:
- Use white/light grey or an appropriately subdued informational treatment.
- Avoid introducing additional bright colors unless required.

## Visual Design Rules

1. Use the corporate palette consistently across applications.
2. Do not introduce additional colors unless explicitly required.
3. Use color primarily to communicate meaning, not decoration.
4. Use "#B7FF00" selectively for active and positive states rather than
   as a general-purpose highlight color.
5. Use white/light grey for primary business information.
6. Use "#C2D2BE" for secondary context and supporting information.
7. Use amber for warnings and HOLD conditions.
8. Use red for overdue, STOPPED, or serious exception conditions.
9. Use subtle panel borders to establish visual structure.
10. Use slightly lighter dark-green rows or panels to distinguish sections
    without introducing additional colors.
11. Avoid excessive use of color, gradients, shadows, or decorative effects.
12. Maintain strong contrast and readability against the dark green
    background.

## Standard Components

Applications should reuse shared components wherever practical:

- AppShell
- Header
- Navigation
- PageHeader
- Button
- Form
- DataGrid
- Card
- Modal
- StatusBadge
- Notification
- ErrorMessage

## Application Header

Every application should display:

- Company identity
- Application name
- Current user
- Application navigation
- Entitlement/access context where appropriate

## AI Implementation Rules

When generating a React/TypeScript application:

1. Import the company theme from the shared foundation.
2. Use the defined corporate color palette and visual design rules.
3. Do not create new brand colors unless explicitly instructed.
4. Do not create application-specific typography.
5. Reuse shared UI components when available.
6. Do not duplicate components already provided by the foundation.
7. Treat this document as the design specification for generated UI.
